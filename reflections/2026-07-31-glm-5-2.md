## On the project

This is the best-engineered small infrastructure project in the workspace.
The security discipline is not decorative — every design decision is
documented with its trade-offs, the cardinal invariant (no signing key) is
AST-enforced by architecture tests, and the CAS-guarded state machine makes
double-issuance structurally impossible rather than conventionally avoided.
The post-issuance SAN + EKU verification on the *result* (not just the
request) is the kind of defense-in-depth that distinguishes "we thought about
template misconfiguration" from "we assumed the template was correct."

The two-identity revocation design — enrollment gMSA (issue-only) vs revoker
gMSA (template-scoped officer, revoke-only) — is the right shape. The
compromise-independence property was proven live (WI-036), and the honest
trade-off documentation for the single-identity `-LocalMode` option is
exactly the kind of explicit, recorded decision this class of infrastructure
demands.

The documentation is exceptional. `docs/operations.md` (864 lines) is a
genuine production runbook. The threat model covers 7 adversary classes with
controls, residuals, and pilot conditions. The pre-pilot checklist with its
validation log (WI-015, WI-028, WI-036) shows a team that takes the "code
works" vs "responsible to run" distinction seriously.

The system has arrived at the right shape. No structural changes recommended.

## On the work done

My initial diagnosis was correct for the version of the script I was looking
at (pre-pull `cb14cc0`): the env var was `ACME_ADCS_RA_FORBIDDEN_IDENTIFIERS`
and `scan_files` returned `tuple[list, list]`. The tests expected
`ACME_RA_FORBIDDEN_IDENTIFIERS` and `list`. I fixed both, ran green, and was
about to commit.

Then `git pull` brought in `39b8a79`, which had independently resolved the
same drift — but in the opposite direction: it reverted the script to its
original API (env var name back to `ACME_RA_FORBIDDEN_IDENTIFIERS`,
`scan_files` back to returning `list[Violation]` with an optional `unreadable`
out-param). The commit message explains this was deliberate: the script is
copied across the estate and the tuple return broke seven repos' test suites.

So I reverted my changes. The tests pass on the current `main` with no local
diff. The lesson: **pull before diagnosing.** I was looking at a stale
working tree and didn't know it — the branch was 4 commits behind origin.

## Gaps to flag

- **Stale working tree went undetected.** The branch was 4 commits behind
  origin/main. Nothing in the session setup surfaced this until `git status`
  showed "behind by 4 commits." Consider whether the orient/start flow should
  auto-pull or at least warn more prominently.
- **The `httpx` deprecation warning** from Starlette's TestClient is
  harmless now but will need attention when FastAPI/Starlette migrates to
  `httpx2`. Not urgent; track as a dependency hygiene item.
- **No `/health` endpoint.** `docs/operations.md` covers monitoring
  thoroughly, but there's no liveness/readiness probe. Only matters if the
  deployment shape changes (containerized, LB-fronted); behind IIS with
  HttpPlatformHandler it's not needed.
- **Git hooks not installed in this environment.** The pre-commit hook
  would have caught the test failure. `scripts/install-git-hooks.sh` exists
  but was never run here.
